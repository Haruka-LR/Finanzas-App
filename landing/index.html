CREATE TABLE transactions (
    id              BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    user_id         BIGINT UNSIGNED NOT NULL,
    account_id      BIGINT UNSIGNED NOT NULL,
    category_id     BIGINT UNSIGNED NULL,
    type            ENUM('INCOME', 'EXPENSE', 'TRANSFER') NOT NULL,
    amount          DECIMAL(15,2)   NOT NULL,
    description     VARCHAR(255)    NOT NULL,
    date            DATE            NOT NULL,
    device_source   VARCHAR(50)     NOT NULL DEFAULT 'PHONE', -- 'PHONE' / 'WEARABLE_WATCH'
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
) ENGINE=InnoDB;
06 // PREGUNTAS Preguntas frecuentes. 問
¿Necesito tener mi reloj conectado a internet para registrar un gasto? +
No. El reloj guarda los gastos de forma local e instantánea, y en cuanto recupera la conexión Bluetooth con tu teléfono o red WiFi, sincroniza los cambios pendientes con la base de datos MySQL.
¿Por qué MySQL en lugar de Firebase o Supabase? +
MySQL te otorga soberanía total sobre tus datos financieros: puedes alojarlo en tu propia Raspberry Pi, tu servidor VPS personal o en tu computadora local. Sin cuotas mensuales ni riesgos de que un servicio en la nube cierre tu cuenta.
¿Qué modelos de smartwatch son compatibles? +
Cualquier reloj con Wear OS 3.0 o superior, incluidos Samsung Galaxy Watch 4/5/6/7, Google Pixel Watch 1/2/3, Xiaomi Watch 2 Pro, TicWatch Pro 5 y OnePlus Watch 2.
¿Cómo se instala y compila el proyecto? +
Basta con abrir el proyecto en Android Studio. El módulo :app compila el APK del teléfono y el módulo :wear compila la versión para el reloj. Para el backend, ejecutas npm start en la carpeta backend/.
